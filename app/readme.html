Overview

Import Microsoft Defender quarantined email into Splunk SOAR or Enterprise Security through Azure Automation. Each message includes its original email, attachments and selected metadata. Importing a message does not release or deny it.

This distribution has its own app UUID and package identity. It does not convert assets belonging to another app. Configure one ingesting asset per tenant; pause previous intake before a controlled replacement.

Requirements and setup

  1. Deploy the companion Azure Automation Runbook 3.7.4 separately. Enable the Automation Account's system-assigned Managed Identity and install the ExchangeOnlineManagement module in its PowerShell runtime.
  2. Grant the Managed Identity Exchange.ManageAsApp and the Exchange/Defender permissions for the quarantine actions you intend to use. Exchange sign-in uses Managed Identity, not the asset's client secret.
  3. Create a runbook webhook. Enter its direct HTTPS URL and the Automation Account coordinates in the asset. Configure a separate App Registration with Automation Job Operator access on that account for reading Azure job status and output. Enter its tenant ID, client ID and client secret value.
  4. Set the Exchange tenant domain in the asset or in the Automation Variable ExchangeOrganization; the asset value takes precedence.
  5. Use one ingesting asset per tenant. Select the source mode and target before starting intake. Configure the container label and schedule in Ingest Settings; disable the schedule to pause automatic imports. Use Poll Now for a manual import. For ES, use the native ES ingest settings and register the five additional fields below.
  6. Configure the analysis playbook's asset bindings, analyst/approver settings, notification recipients, portal links and routing label before activation. For SOAR, start analysis from the completed mail's ready artifact.

Native email import requires authenticated local SOAR REST access, including when importing into SOAR rather than ES. Automation Broker is not supported; SOAR Cloud compatibility has not been verified.

Email import

on_poll_max_containers is a maximum of simultaneously unresolved Microsoft quarantine identities, configurable 1–50 and default 10. It is not a per-poll increment. The app checks tracked IDs read-only; exact Released or Denied frees slots. It fills free slots from the existing first 50 source-status candidates. Missing IDs, errors, other statuses and analysis completion do not free slots. An empty import does not prove an empty backlog; no pagination or stable ordering is promised.

Selection release_requested means Microsoft Requested; needs_review means NotReleased. Needs review is explicit opt-in and may process mail without a recipient request. Check your tenant's Deny eligibility before using it with NotReleased messages. A mail intentionally left unchanged can occupy a slot indefinitely.

New SOAR events are named Subject: <email subject>; subjectless mail keeps the existing Quarantine release request fallback.

Original email and attachments are saved automatically to the container's Vault. Selected mail fields are always added as artifacts, using the chosen combined/separate layout. The combined overview is named after the email subject (No subject if absent); field selections control its content, not its name. All preparation suppresses automation. SOAR publishes a final ready artifact only after preparation; use its ingestionReady=true, quarantineIdentity and original-mail vaultId. ES uses the configured native threat-analysis and automation settings instead; publication acceptance does not prove that an analysis workflow finished.

Native ES prerequisites

Register quarantine_identity, work_item_id, source_data_identifier, quarantine and eml_sha256 as accepted additional fields in the target ES environment. The app does not register them. Configure a valid security domain; urgency and investigation type are optional native settings. Analyst download links use the validated external HTTPS base URL from SOAR system information. Test their reachability and mail/attachment rendering from the analyst interface. ES is a lossy projection: the outer message body prefers plain text, then HTML; attachment-marked parts, file-named parts and attached-message descendants are excluded. Related MIME uses its declared root (or first part). Header values are limited to 8192 characters and body to 256000 characters. The 2 MiB metadata check precedes attachment-link entries and is not a complete final-request size guarantee. The original EML in Vault remains authoritative.

Configuration

Configure the Azure connection, email selection and active-message limit, selected mail fields, and advanced job settings below. The ingest schedule is set in SOAR/ES Ingest Settings; the Azure polling interval and timeout monitor individual Azure jobs, not the mail-import schedule.

The SOAR URL override applies to both SOAR and ES email import. Azure connections require HTTPS and certificate verification; webhook redirects are not followed. Configure the platform's trusted CA store for private certificates.

Available actions

Release and Deny run only when invoked by an operator or playbook. The app confirms the resulting Microsoft status before reporting a successful disposition.

test connectivity

Validates webhook reachability and Azure AD token acquisition

No parameters.

on poll

Email import: save complete quarantine emails and attachments in SOAR containers. Check Microsoft status and refill the active-message window.

  • start_time (optional): Ignored.
  • end_time (optional): Ignored.
  • container_count (optional): Maximum containers for Poll Now (1-50).
  • artifact_count (optional): Ignored.
  • container_id (optional): Ignored.

recover quarantine ingestion

Import recovery: retry blocked preparation or confirm an uncertain publication.

  • identity (required): Quarantine message Identity.
  • resolution (required): Explicit ingestion recovery resolution. Choices: retry_preparation, confirm_published.
  • operator_note (required): Operator recovery rationale and publication verification evidence.

inspect release environment

Read-only inspection of the deployed runbook, loaded Exchange cmdlet contract, and one exact quarantine identity; optional tenant RBAC inspection requires explicit opt-in

  • identity (required): Exact quarantine Identity in GUID1\GUID2 form. The diagnose action reads this identity but never releases or denies it.
  • include_rbac (optional): Explicitly opt in to tenant-wide read-only RBAC and role-group diagnostics after the exact quarantine identity has been bound. Defaults to false.

release quarantine message

Release a quarantined message to all original recipients

  • identity (required): Quarantine message Identity in the exact format GUID1\GUID2 (e.g. c14401cf-aa9a-465b-cfd5-08d0f0ca37c5\4c2ca98e-94ea-db3a-7eb8-3b63657d4db7). Use cef.quarantineIdentity from the ingested SOAR ready artifact or quarantine_identity from the ES finding. The format is validated before the webhook fires - malformed values fail immediately without starting a runbook job.
  • operation_id (optional): Stable idempotency key for this logical release. Reusing the same value suppresses another webhook while its operation record is retained. Terminal records may be evicted at the 50-record registry limit; this is not permanent idempotency protection. If omitted, the connector derives a stable key from the SOAR container, action, and identity.

deny quarantine release

Deny a user's request to release a quarantined message

  • identity (required): Quarantine message Identity in the exact format GUID1\GUID2 (e.g. c14401cf-aa9a-465b-cfd5-08d0f0ca37c5\4c2ca98e-94ea-db3a-7eb8-3b63657d4db7). Use cef.quarantineIdentity from the ingested SOAR ready artifact or quarantine_identity from the ES finding. The format is validated before the webhook fires - malformed values fail immediately without starting a runbook job.
  • operation_id (optional): Stable idempotency key for this logical deny. Reusing the same value suppresses another webhook while its operation record is retained. Terminal records may be evicted at the 50-record registry limit; this is not permanent idempotency protection. If omitted, the connector derives a stable key from the SOAR container, action, and identity.

reconcile quarantine operation

Read an existing Azure job and optionally refresh the exact Exchange status without a disposition call

  • azure_job_id (required): Existing Azure Automation job UUID recorded by the original release or deny action.
  • expected_action (required): Irreversible action the existing job was expected to execute. Choices: release, deny.
  • expected_identity (required): Exact quarantine identity expected in the validated runbook result.
  • operation_id (optional): Optional stable operation ID from the original action. When omitted, the connector resolves it from the Azure job ID or creates a durable read-only observation.
  • refresh_exchange_status (optional): Explicitly start one read-only runbook reconciliation to obtain a fresh exact Exchange ReleaseStatus. No release or deny cmdlet is permitted.

on es poll

Email import: publish to ES with app-managed Microsoft status checks and active-message limits.

  • start_time (optional): Ignored.
  • end_time (optional): Ignored.
  • container_count (optional): Maximum containers for Poll Now (1-50).
  • artifact_count (optional): Ignored.
  • container_id (optional): Ignored.

Maintenance and removal

Back up the app, asset configuration and app state using the platform backup procedure. Stop ingestion and dependent automation before removing the app. Resolve pending operations before restoring a backup; do not clear state to restart processing or resubmit an operation with an unknown outcome.

Failures and recovery

Retryable preparation and definitive publication rejection can retry on a later poll. Timeout, lost or mismatched receipt, server failure and unknown acceptance remain publishing; no blind resubmission. Deterministic MIME/size failures remain blocked. Use recover quarantine ingestion with an exact identity and an evidence-based operator note. Retry preparation only after its underlying problem is fixed; confirm published only after independently verifying the existing exact artifact/finding and workflow. Recovery does not free a Microsoft-status-controlled slot or dispatch analysis by itself.

  • retry_preparation is allowed only from blocked, reserved, preparing or ready. It resets to preparing with a bound container, otherwise reserved; a later poll resumes preparation. It cannot reset publishing or published items.
  • confirm_published is allowed only from publishing. Verify the existing exact ready artifact or ES finding, linked container and native automation execution independently, and record evidence in the required operator note. This operator assertion marks published without sending another submission; the app does not verify that evidence itself.

For uncertain Release/Deny outcomes use read-only reconciliation before any new write. A genuine Microsoft error is not proof that no effect occurred. No polling operation calls Release/Deny.

Limits and data handling

EML cap: 24 MiB. MIME limits: 200 parts, nesting depth 30, 100 attachments, 48 MiB combined decoded attachments. Native ledger cap: 1000 records; active items are not evicted. Terminal retention is configurable 1–365 days, default 30. Retention expiry can allow reappearing source records to be admitted again; there is no global exactly-once guarantee. A 600-second between-call poll budget defers remaining work; one in-flight operation may run longer.

Mail and attachments may contain sensitive content or malware. Original mail travels from Exchange through Azure Automation to SOAR/Vault; ES receives finding metadata and mail/file links. Apply platform permissions, retention and handling policies to jobs, Vault, state and evidence. No credentials are stored in this help. Do not include message bodies, tokens or webhook URLs in support reports.

Troubleshooting and support

If an action fails, record the app and runbook versions, SOAR/ES versions, selection mode, action error and Azure job ID. Check the job output and use read-only reconciliation for an uncertain disposition. Do not include client secrets, webhook tokens or message contents in support reports.
