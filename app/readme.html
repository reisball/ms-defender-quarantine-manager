Import Microsoft Defender quarantine mail with a recipient release request (Requested). Import does not release or deny mail.

Quick start

  1. Publish the matching Azure Automation Runbook 1.0.0 separately. Use the supported PowerShell runtime with ExchangeOnlineManagement and a system-assigned Managed Identity with the required Exchange quarantine permissions.
  2. Configure one ingesting asset per tenant. The direct HTTPS webhook starts jobs; the separate Entra app registration only reads job status and output. Pause any previous intake for the tenant before switching.
  3. Run test connectivity, then configure the target and schedule in Ingest Settings. Use Poll Now with controlled test mail before enabling the schedule or playbooks.

Use native SOAR execution with authenticated local REST access. Automation Broker is not supported. See the asset and action forms for field and parameter details.

Choose an import target

  • SOAR events: Set a container label. Original email and attachments are saved automatically to the Vault. Combined layout publishes exactly one email artifact after the uploads; it references the original EML. Separate-field SOAR layout uses a final Ready artifact. For the optional SAA example, import the inactive playbook and set its asset bindings, event label and approver before enabling it.
  • ES findings (optional): Enable the native ES target and set its security domain. No custom ES fields are required. ES receives mail headers, body text (up to 256,000 characters), and Vault download links. Attachment content stays in the SOAR Vault; verify the external HTTPS download URL from the analyst interface. A finding receipt does not mean analysis has finished.

For Release/Deny, use container:data.quarantine_identity from the SOAR event, or from the linked SOAR container when working in ES.

Import limits and troubleshooting

The active-message limit is 1–50 (default 10); it is not a per-poll count. Failed imports can still occupy slots. The app considers the first 50 eligible candidates and does not guarantee pagination. The original EML limit is 24 MiB.

What you seeWhat to do
Import failedRead the action error and inspect any existing event, Vault files or ES finding. Once the cause is fixed, use Poll Now to retry an eligible message. If the ES response was lost, check for an existing finding first: a retry could duplicate it.
Release/Deny failed, is pending or is unknownRead the outcome and error code. Inspect the original Azure job if its ID is known, otherwise check job history and the current Microsoft status using inspect release environment. A failure does not rule out a remote effect; a timeout does not cancel Azure. Do not start another disposition while one is pending or before resolving an unknown outcome.
Connectivity or download failedCheck the matching runbook, webhook, job-reader permissions and Exchange identity. For ES links, check the HTTPS address and analyst access.

Backup and removal

Back up the app package, asset settings and app state securely. Before removal or restore, pause intake and dependent playbooks and check unresolved jobs and imports. Restoring older state can roll back import records. Never clear app state to force a retry.

Do not share webhook URLs, secrets or quarantined mail in support reports. Include app and runbook versions, the action error and any known Azure job ID.
